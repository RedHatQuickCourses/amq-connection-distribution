Configuring broker-side security credentials and passwords

Configuring Broker-Side Security Credentials and Passwords

When integrating AMQ Broker with Red Hat Build of Keycloak (RHBK), securing the broker involves managing how it interacts with the identity provider. Instead of relying on local flat-file credentials for every connection, the broker utilizes JAAS (Java Authentication and Authorization Service) configurations to delegate authentication to Keycloak.

This section covers how to configure the broker-side security credentials, specifically focusing on the creation of JAAS configuration secrets and the definition of the login.config file.

Understanding the Security Architecture

To secure AMQ Broker with Keycloak, you must define the authentication modules that the broker should use. This is achieved via a login.config file, which defines the console (for management access) and activemq (for messaging client access) domains.

Key components for this configuration include: * BearerTokenLoginModule: Used for validating incoming bearer tokens from Keycloak. * DirectAccessGrantsLoginModule: Allows the broker to validate user credentials directly against Keycloak. * Keycloak Config Files: JSON files defining the realm, resource, and client secrets required to communicate with the RHBK server.

Hands-On Activity: Configuring JAAS and Broker Secrets

In this activity, you will prepare the security artifacts required for the broker to authenticate users against Keycloak.

Step 1: Create the Keycloak Configuration Files

The broker requires specific JSON configuration files to communicate with your Keycloak instance. Create these files locally using the following templates:

export KEYCLOAK_URL=keycloak-sso.apps.com

# Create the Direct Access Grants configuration
cat <<EOF | envsubst > _keycloak-direct-access.json
{
  "realm": "amq-broker-realm",
  "auth-server-url": "https://${KEYCLOAK_URL}",
  "ssl-required": "all",
  "credentials": {
    "secret": "amq-broker-secret-value"
  },
  "resource": "amq-broker",
  "use-resource-role-mappings": true,
  "principal-attribute": "preferred_username",
  "verify-token-audience": true,
  "enable-basic-auth": true,
  "confidential-port": 0
}
EOF

# Create the Bearer Token configuration
cat <<EOF | envsubst > _keycloak-bearer-token.json
{
  "realm": "amq-broker-realm",
  "auth-server-url": "https://${KEYCLOAK_URL}",
  "ssl-required": "all",
  "resource": "amq-broker",
  "use-resource-role-mappings": true,
  "principal-attribute": "preferred_username"
}
EOF

Step 2: Define the JAAS login.config

The login.config defines how the broker handles login requests. It chains login modules to ensure that if one fails, it can fall back or proceed to the next requirement.

Create a login.config file with the following structure:

console {
    org.apache.activemq.artemis.spi.core.security.jaas.PropertiesLoginModule sufficient
        org.apache.activemq.jaas.properties.user="artemis-users.properties"
        org.apache.activemq.jaas.properties.role="artemis-roles.properties"
        baseDir="/home/jboss/amq-broker/etc";
    org.keycloak.adapters.jaas.BearerTokenLoginModule sufficient
        keycloak-config-file="${secret.mount}/_keycloak-bearer-token.json"
        role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.RolePrincipal;
};

activemq {
    org.keycloak.adapters.jaas.BearerTokenLoginModule sufficient
        keycloak-config-file="${secret.mount}/_keycloak-bearer-token.json"
        role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.RolePrincipal;
    org.keycloak.adapters.jaas.DirectAccessGrantsLoginModule sufficient
        keycloak-config-file="${secret.mount}/_keycloak-direct-access.json"
        role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.RolePrincipal;
};

Step 3: Create the OpenShift Secret

Finally, bundle these files into an OpenShift secret. The broker operator will mount this secret into the broker container to access the configuration.

oc create secret generic keycloak-jaas-config \
  --from-file=login.config \
  --from-file=_keycloak-direct-access.json \
  --from-file=_keycloak-bearer-token.json \
  --from-file=artemis-users.properties \
  --from-file=artemis-roles.properties

Ensure that the secret.mount path defined in your login.config matches the volume mount path configured in your AMQ Broker Custom Resource (CR). If you change the mount location, you must update the path in the JAAS file accordingly.
