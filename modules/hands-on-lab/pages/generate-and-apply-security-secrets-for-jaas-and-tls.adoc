#  Generate and apply security secrets for JAAS and TLS

= Generate and apply security secrets for JAAS and TLS

To secure an AMQ Broker instance using Keycloak 26, you must provide the broker with the necessary credentials and trust material via Kubernetes Secrets. This ensures the broker can authenticate users via the `BearerTokenLoginModule` and establish encrypted connections for the management console.

== Generating JAAS Authentication Secrets

The JAAS (Java Authentication and Authorization Service) configuration defines how the broker validates identities. To integrate Keycloak, you must package your login configuration into a secret that the broker pod can mount.

1. Create a `login.config` file that combines your properties-based login (for administrative fallback) and the Keycloak `BearerTokenLoginModule`:

[source,bash]
----
cat <<"EOF" > login.config
console {
    org.apache.activemq.artemis.spi.core.security.jaas.PropertiesLoginModule sufficient
        org.apache.activemq.jaas.properties.user="artemis-users.properties"
        org.apache.activemq.jaas.properties.role="artemis-roles.properties"
        baseDir="/home/jboss/amq-broker/etc";

    org.keycloak.adapters.jaas.BearerTokenLoginModule sufficient
        keycloak-config-file="${secret.mount}/_keycloak-direct-access.json"
        role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.RolePrincipal;

    org.apache.activemq.artemis.spi.core.security.jaas.PrincipalConversionLoginModule required
        principalClassList=org.keycloak.KeycloakPrincipal;
};
EOF
----

2. Create the Kubernetes secret. If you are using property files for user management, include them in the secret creation command:

[source,bash]
----
oc create secret generic keycloak-jaas-config \
  --from-file=login.config \
  --from-file=artemis-users.properties \
  --from-file=artemis-roles.properties
----

== Managing TLS Certificates for HTTPS

The AMQ Broker management console requires a Java Keystore (JKS) to serve traffic over HTTPS. You must provide the server certificate and the truststore (containing the CA that signed the Keycloak/Broker certificates).

1. Download or generate your keystore and truststore files. For testing purposes, you can retrieve standard resources:

[source,bash]
----
wget -O server-keystore.jks https://github.com/apache/activemq-artemis/raw/main/tests/security-resources/server-keystore.jks
wget -O client-ca-truststore.jks https://github.com/apache/activemq-artemis/raw/main/tests/security-resources/client-ca-truststore.jks
----

2. Create the TLS secret containing the keystore, truststore, and their respective passwords:

[source,bash]
----
oc create secret generic ext-acceptor-ssl-secret \
  --from-file=broker.ks=server-keystore.jks \
  --from-file=client.ts=client-ca-truststore.jks \
  --from-literal=keyStorePassword=securepass \
  --from-literal=trustStorePassword=securepass
----

== Verification
After applying the secrets, ensure they are visible within your namespace:

[source,bash]
----
oc get secret keycloak-jaas-config
oc get secret ext-acceptor-ssl-secret
----

[NOTE]
====
Ensure the `keyStorePassword` and `trustStorePassword` match the passwords used when creating the JKS files. Mismatched passwords will prevent the AMQ Broker console from initializing the SSL acceptor, leading to boot-time failures.
====
