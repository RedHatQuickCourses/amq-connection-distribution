#  Configuring Keycloak JAAS authentication secrets

= Configuring Keycloak JAAS Authentication Secrets

To integrate Red Hat AMQ Broker with Keycloak, you must configure the Java Authentication and Authorization Service (JAAS). This allows the broker to delegate authentication and authorization tasks to Keycloak using a custom login module.

== Understanding the JAAS Configuration

The AMQ Broker requires a `login.config` file that defines the security domain. When using Keycloak, this configuration must map the `KeycloakLoginModule` to the broker's security requirements, defining how the broker interprets roles and principals.

The configuration typically involves:
* **`org.keycloak.adapters.jaas.DirectAccessGrantsLoginModule`**: Used for validating direct access credentials.
* **`org.keycloak.KeycloakPrincipal`**: The class used to handle the authenticated user's identity.
* **`RolePrincipal` mapping**: Ensuring that roles provided by Keycloak are correctly mapped to AMQ Broker security roles.

== Implementation Steps

To configure the secret in OpenShift, follow these steps to define the JAAS login module and store it as a Kubernetes Secret.

=== Step 1: Create the Login Module Configuration

Create a file named `login.config` on your local machine. This file defines the JAAS stack that the broker will use to communicate with your Keycloak instance.

[source,text]
----
activemq {
    org.keycloak.adapters.jaas.DirectAccessGrantsLoginModule required
        keycloak-config-file="/etc/keycloak/keycloak-direct-access.json"
        role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.RolePrincipal;

    org.apache.activemq.artemis.spi.core.security.jaas.PrincipalConversionLoginModule required
        principalClassList=org.keycloak.KeycloakPrincipal;
};
----

[NOTE]
Ensure that the `keycloak-config-file` path matches the mount point where you will eventually mount the Keycloak configuration JSON file within the AMQ Broker pod.

=== Step 2: Create the Kubernetes Secret

Once the `login.config` file is defined, wrap it into a Kubernetes Secret. This allows the AMQ Broker operator to mount the configuration into the broker instance securely.

Run the following command in your terminal:

[source,bash]
----
oc create secret generic keycloak-jaas-config \
  --from-file=login.config=login.config \
  -n <your-broker-namespace>
----

=== Step 3: Verifying the Secret

After creation, verify that the secret contains the configuration data correctly:

[source,bash]
----
oc get secret keycloak-jaas-config -n <your-broker-namespace> -o yaml
----

The output should show the `login.config` content encoded in base64 within the `data` field.

== Troubleshooting Tips

* **Principal Class Mismatches**: Ensure that `role-principalclass` in your JAAS config matches the expectation of your security settings defined in `broker.xml`.
* **Missing JSON Config**: The `keycloak-direct-access.json` referenced in the `login.config` must also be created as a separate secret and mounted to the broker pod. If the broker fails to start, check the logs for `FileNotFoundException` related to the configuration path.
* **Namespace Scope**: Ensure the secret is created in the same namespace where the AMQ Broker custom resource (CR) is deployed; otherwise, the broker pod will fail to mount the secret.
