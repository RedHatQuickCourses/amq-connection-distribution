#  Create Kubernetes secrets for JAAS configuration and token authentication

= Create Kubernetes secrets for JAAS configuration and token authentication

To secure AMQ Broker with Keycloak, you must provide the broker with the necessary configuration to validate bearer tokens and manage authentication requests. This is achieved by creating Kubernetes Secrets that store the JAAS (Java Authentication and Authorization Service) configuration file and the Keycloak client integration JSON files.

== Understanding the JAAS Configuration

The JAAS configuration file defines the login modules the broker uses to authenticate users. When integrating with Keycloak, we typically combine local property-based authentication (for fallback or management) with the `BearerTokenLoginModule` (for token validation).

The configuration is split into two primary domains:
* **`console`**: Defines how the web management console authenticates users.
* **`activemq`**: Defines how messaging clients authenticate when connecting to the broker.

== Hands-on Lab: Provisioning Secrets

In this activity, you will create the necessary configuration files and wrap them into Kubernetes secrets for the AMQ Broker to consume.

### Step 1: Create the JAAS Configuration File

Create a local file named `login.config` that defines the authentication stack. This configuration leverages the Keycloak adapter modules.

[source,bash]
----
cat <<EOF > login.config
console {
  org.apache.activemq.artemis.spi.core.security.jaas.PropertiesLoginModule sufficient
    org.apache.activemq.jaas.properties.user="artemis-users.properties"
    org.apache.activemq.jaas.properties.role="artemis-roles.properties"
    baseDir="/home/jboss/amq-broker/etc";
  org.keycloak.adapters.jaas.BearerTokenLoginModule sufficient
    keycloak-config-file="${secret.mount}/_keycloak-bearer-token.json"
    role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.RolePrincipal;
  org.apache.activemq.artemis.spi.core.security.jaas.PrincipalConversionLoginModule required
    principalClassList=org.keycloak.KeycloakPrincipal;
};

activemq {
  org.keycloak.adapters.jaas.BearerTokenLoginModule sufficient
    keycloak-config-file="${secret.mount}/_keycloak-bearer-token.json"
    role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.PrincipalConversionLoginModule;
  org.keycloak.adapters.jaas.DirectAccessGrantsLoginModule sufficient
    keycloak-config-file="${secret.mount}/_keycloak-direct-access.json"
    role-principalclass=org.apache.activemq.artemis.spi.core.security.jaas.RolePrincipal;
  org.apache.activemq.artemis.spi.core.security.jaas.PrincipalConversionLoginModule required
    principalClassList=org.keycloak.KeycloakPrincipal;
};
EOF
----

### Step 2: Prepare Keycloak Integration JSONs

Ensure you have your Keycloak client configuration files (`_keycloak-bearer-token.json` and `_keycloak-direct-access.json`) ready, as referenced in the `login.config` file above. These files contain the Realm, Client ID, and URL required for the broker to communicate with the Keycloak server.

### Step 3: Create the Kubernetes Secret

Once the files are prepared, create the Kubernetes secret in your target namespace. This secret will be mounted into the AMQ Broker pod.

[source,bash]
----
# Create the secret containing the JAAS config and the Keycloak JSON files
oc create secret generic keycloak-jaas-config \
  --from-file=login.config \
  --from-file=_keycloak-bearer-token.json \
  --from-file=_keycloak-direct-access.json \
  --from-file=artemis-users.properties \
  --from-file=artemis-roles.properties \
  -n amq-broker-namespace
----

[NOTE]
====
Replace `amq-broker-namespace` with the actual namespace where your AMQ Broker is deployed.
====

### Troubleshooting Tips
* **Mount Path Verification**: Ensure the `${secret.mount}` variable in your `login.config` matches the actual mount path defined in your `ActiveMQArtemis` custom resource (typically `/etc/secrets/keycloak`).
* **Secret Contents**: Use `oc get secret keycloak-jaas-config -o yaml` to verify that all required keys are present and correctly encoded.
* **Typo Checks**: JAAS files are sensitive to whitespace and class name spelling. Ensure that no accidental line breaks exist within the module definitions.
